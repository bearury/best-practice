2 Команды деплоя важно!

TR

(build and push local)
make build VERSION=3.45.11-5
make push VERSION=3.45.11-5

Deploy TR

dev (rel | prod) 
make deploy VERSION=3.45.11-5 CONFIGURATION=dev PORT=81

TRS

(prod)
make deploy VERSION=0.0.29-10 SERVER_ENV=prod
Зачем? Один коммит = одна задача. Тогда cherry-pick берёт всю задачу целиком без проблем.

4 Частые команды Docker осторожно

Удалить контейнер и все его image и values
docker rm -fv <имя_или_id_контейнера>
Если собрано через docker compose
docker compose down -v
Каждая строка = одна задача (благодаря squash). Берёшь хеш нужных.

5 Собрать релиз внимательно

создать ветку релиза от последнего прода

# Если main не чистый — от последнего тега
git checkout -b release/2.5.0 v2.4.0

# Или от main если он чистый
git checkout main
git checkout -b release/2.5.0

cherry-pick только нужные задачи

# Берём задачи 45 и 41, НЕ берём 38 и 52
git cherry-pick 2c9eeb6b  # TASK-45
git cherry-pick i9j0k1l2  # TASK-41

# Тестируем → если ОК → пуш
git push -u origin release/2.5.0

или если все задачи:

git cherry-pick main..develop

6 Версионирование на подумать !!!!

⚡ Конфликты при cherry-pick

Ситуация Команда
Отменить cherry-pick git cherry-pick --abort
Решить и продолжить git add . && git cherry-pick --continue
Пропустить коммит git cherry-pick --skip
Посмотреть конфликты git diff --name-only --diff-filter=U
Конфликты чаще если задачи меняют одни файлы. Squash уменьшает шанс конфликтов.

🔧 Полезные команды

Что Команда
Разница develop vs main git log --oneline main..develop
Файлы в коммите git diff-tree --no-commit-id --name-only -r HASH
Сравнить 2 ветки git diff branch1..branch2 --stat
Все ветки с upstream git branch -vv
Список тегов git tag -l --sort=-v:refname
Сохранить коммит на ветку git branch backup/name HASH
Применить коммит git cherry-pick HASH
Отменить последний коммит git reset --soft HEAD~1
